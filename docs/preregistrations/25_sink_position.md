# 预注册 25：sink 突跳是否跟着 sink 的旋转位置距离走？把 sink 固定在探针峰值距离上，是否比固定在谷值保留得更多？（Self Forcing，60 秒）（2026-10-28，生成前冻结）

## 背景
- sink 留在原始（绝对）旋转位置时，持续度在约 17、33、51 秒突然上升（"突跳"），开头的场景内容也在这些时刻回来：
  - Self Forcing 的 5 个 checkpoint 和 LongLive 都是如此（预注册 10、16、21）；
  - 重新旋转的 sink 和无 sink 的配置从不出现。
- 推测的机制：sink 的键随生成离当前块越来越远；在某些查询–sink 距离上，模型会把大量注意力分给 sink，开头因此被重新注入。
- **探索性的注意力探针**（`jobs/run_sinkprobe.sh`，`analyze_sinkprobe.py`，不属于任何预注册）：
  - 设置：4 个未平移的开头（rx00、rx01、gx00、gx01），sink 3，原始位置；每个开头 20 个块（起点 12、24、…、240），每个块 128 个随机查询，30 层、5 次注意力调用（4 个去噪步 + 1 次上下文）。
  - 测量：对网格中每个距离 D（3–300 个潜在帧），如果把 sink 放在距离 D，查询会分给 sink 多少注意力（sink 与窗口的 logsumexp 比较）。
  - 结果（`sinkprobe_out.json`）：分给 sink 的份额在 D = 71、134、203、266 处出现尖峰（0.109、0.136、0.150、0.098；3 ≤ D ≤ 300 的中位数为 0.073），每个峰宽约 4 个潜在帧；每个峰之前有一个谷（例如 D = 187 处为 0.052，D = 123 处为 0.055）。
  - 4 个开头、所有块的峰都在完全相同的距离上，所以这是模型位置编码的性质，与内容无关。
  - 在原始位置下，块的自然距离在开头之后 16.5、32.25、49.5 秒到达 71、134、203，正好是观察到的突跳时间。
- **一致性检查：** 打补丁的 Self-Forcing-b 在不开开关时与预注册 10 的输出逐位相同（rx00，sink 3，m16，A40）。
- **设计检查（使用预注册 10 已有的数据）：** 用下文定义的突跳窗口，原始位置 sink 3 的突跳对比为 +0.33 [0.29, 0.38]，重新旋转的 sink 为 −0.04。
- 本研究通过干预 sink 的位置检验两件事：
  - 突跳是由距离决定的，而不是由开头之后经过的时间或内容决定；
  - 把 sink 固定在峰值距离上，是否比固定在谷值或窗口旁边保留得更多。

## 设计
- **场景：** 预注册 06 的 24 个场景（rx00–rx11、gx00–gx11），通用提示词（`prompts/relax.jsonl`）。
- **模型：** Self Forcing DMD，sink 3，窗口 21，60 秒（243 个潜在帧）。
  - 生成器 `hold_gen_sinkpos.py`，在 Self-Forcing-b 中运行（只有 `wan/modules/causal_model.py` 是 `jobs/patch_sf_sinkpos.py` 打过补丁的实际文件）。
  - 补丁只旋转 sink 键的一份拷贝（缓存保留原始的键），与 `patch_sf.py` 的重新旋转相同。
- **开头：** L\* 平移 −16 / +16（版本 m16、p16），与预注册 06、10 相同。
- **种子：** 0。
- **条件：**
  - sp_abs：原始位置（不加开关）；
  - sp_off18：sink 往后移 18 个潜在帧（`--sink_mode off:18`），距离 = 自然距离 + 18；
  - sp_off36：往后移 36 个潜在帧（`off:36`）；
  - sp_d203：sink 固定在距离 203（探针峰值，`dist:203`）；
  - sp_d187：固定在距离 187（峰值前的谷，`dist:187`）；
  - sp_d20：固定在距离 20（紧挨窗口，相当于重新旋转，`dist:20`）。
- **执行：**
  - 每个场景一个任务，包含所有条件和版本（12 个视频）；arch_guard 保证一个场景的所有输出来自同一 GPU 架构；
  - GPU 不限型号（≥ 40 GB，支持 bf16）；
  - 只为 rx00、gx00 写视频文件；
  - 任务清单由 `make_s25_tasks.py` 生成（`jobs/s25.jsonl`，24 个任务）。
  - 共 24 × 6 × 2 = 288 个视频。
- 生成器在 npz 中另外记录两个逐帧量：motion（与前一帧的平均灰度绝对差，0–100）和 open_diff（与第 8 帧，即开头最后一帧的平均灰度绝对差）。

## 指标
- α[t0, t1) = (end_p16 − end_m16) / (open_p16 − open_m16)：
  - open 是第 1–8 帧的 L\* 均值；
  - end 是开头之后 [t0, t1) 秒的 L\* 均值；
  - 若 open_p16 − open_m16 < 4 L\*，则无定义。
- 没有坍塌排除规则。
- **突跳起点：**
  - 一个从潜在帧 c 开始的块，到 sink 第 0 帧的距离是 c + 2 + δ（δ 是 sink 额外后移的帧数：0、18、36），这个块从开头之后 (c − 3)/4 秒开始。
  - 所以突跳起点为 τ_k(δ) = (P_k − 5 − δ)/4 秒，P = 71、134、203、266。
  - 突跳窗口 W_k = [τ_k + 0.5, τ_k + 2.5) 秒，只保留落在 [5, 60) 秒内的窗口：
    - δ = 0：16.5、32.25、49.5 秒；
    - δ = 18：12、27.75、45 秒；
    - δ = 36：7.5、23.25、40.5、56.25 秒。
  - A_X(δ)：条件 X 在 δ 对应的所有窗口上的 α 均值（每个场景一个值）。

## 假设（`analyze_s25.py`，冻结；Holm 校正，共 4 个检验）
- **H1 突跳跟着 18 帧的移动走：** [A_off18(18) − A_off18(0)] − [A_abs(18) − A_abs(0)] > 0。
- **H2 突跳跟着 36 帧的移动走：** [A_off36(36) − A_off36(0)] − [A_abs(36) − A_abs(0)] > 0。
- **H3 峰值距离比谷值保留得更多：** α(sp_d203, [50, 60)) − α(sp_d187, [50, 60)) > 0。
- **H4 峰值距离比距离 20 保留得更多：** α(sp_d203, [50, 60)) − α(sp_d20, [50, 60)) > 0。
- **检验方法：**
  - 以场景为单位的双侧单样本 t 检验；
  - Holm p < 0.05 且估计 > 0 为成立；
  - 95% CI 用场景 bootstrap（10,000 次）。
- 如果突跳只由时间（或开头之后的内容变化）决定，H1、H2 的两个括号相等，估计为 0。

## 次要分析
- [40, 50) 秒窗口的 H3、H4；
- 每个条件在自己的突跳起点上的对比：mean_k [α(W_k) − α([τ_k − 2.5, τ_k − 0.5))]；
  - sp_abs、sp_off18、sp_off36 用各自的 δ；
  - sp_d203、sp_d187、sp_d20 用 δ = 0 的起点；
- 每个条件 1 秒曲线上大于 0.15 的跳变出现的时间，与预测的起点对照；
- 每个条件 T = 10, 20, …, 60 秒的 α（10 秒窗口）和 1 秒曲线；
- 探针对照：在 t = 6…59 秒上，sp_abs、sp_off18、sp_off36 平均 1 秒 α 曲线的一阶差分，与探针在 δ = 0、18、36 下预测的 sink 份额的一阶差分的相关；
- 每个条件 [50, 60) 秒的平均 motion 和 open_diff（两个版本都计入）：检查固定在峰值距离是否让视频冻结或复制开头。

## 预测
- **H1、H2 成立：** 突跳提前约 4.5 秒和 9 秒。
- **H3 成立：** 距离 203 处 sink 得到的注意力约为 187 处的 3 倍。
  - 幅度不确定：持续把注意力分给 sink，也可能导致视频偏向复制开头（看 motion 和 open_diff）。
- **H4 成立。**
- **解读规则：**
  - 若 H1、H2 不成立（突跳仍在原来的时刻），突跳不是由距离决定的，论文里的位置解释要撤回。
  - 若 H1、H2 成立而 H3 不成立：突跳的时刻由距离决定，但把 sink 停在峰值距离并不能持续保留更多。突跳是距离经过峰值时的瞬时响应。
  - 若 H3、H4 成立：把 sink 放在峰值距离是一个不需要训练的方法，可以持续保留开头。是否有代价，看 motion 和 open_diff。
