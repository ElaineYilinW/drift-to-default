# Preregistration 22: does the 14B model Krea Realtime forget the opening, and does a first-frame anchor keep a share? (2026-10-27, frozen before generation)

*English translation; the Chinese file `../22_krea.md` is the frozen, authoritative version.*

## Background
- Six of the eight models in the paper are based on Wan2.1-1.3B. Whether scale changes the conclusions has not been tested.
- Krea Realtime 14B is an autoregressive model distilled from Wan2.1-T2V-14B with Self Forcing; its weights and inference code are public. Its long-video design differs from the models in the paper:
  - before each block (3 latent frames) is generated, the KV cache is **recomputed** from the clean latents of the most recent 3 latent frames, with positions restarting from 0; frames that have left the window cannot leak information through the cache;
  - the window's first context frame is obtained by re-encoding the oldest decoded frame in the window (the released default setting), so the opening leaves the context after two blocks;
  - the released code has a `keep_first_frame` option: the opening's first latent frame always serves as the first context frame (positioned before the window, equivalent to a re-rotated sink, but taking up one third of the context). Krea's technical note says this anchoring "limits how far the video departs from the first frame", but leaves artifacts.
- The paper's conclusions give clear predictions:
  - a model that reads the opening only through its window forgets the opening (MAGI-1's released window, Self Forcing without a sink);
  - an opening that stays in the context keeps a share (re-rotated sink about 0.2, MAGI-1 full history 0.64).
- This study tests these two points on the 14B model, for both tone and scene content.

## Design
- **Model:** Krea Realtime 14B (`krea-realtime-video-14b.safetensors`), the released inference code (GenerationSession of `release_server.py`), configuration `self_forcing_server_14b.yaml`:
  - 3 latent frames per block, kv_cache_num_frames = 3, KV recomputation;
  - number of denoising steps and timesteps at the GenerateParams defaults;
  - 832 × 480, 16 fps.
  - Argon can only install torch 2.6, so `jobs/patch_krea.py` makes two compatibility changes (a dynamo config name; removing one flex_attention speed hint), which do not change the computation.
  - To fit into 48 GB of GPU memory: the text encoder is first run once on the GPU and then freed; the 14B transformer is built on the CPU, the weights are loaded, it is converted to bf16 and then moved to the GPU. This is the same computation as the released code.
  - After fusing the q/k/v projections, the released code still keeps the unfused copies (about 6 GB, not used afterwards); here they are deleted before moving to the GPU.
  - When the released code uses a start frame, the start frame's 3 latent frames occupy the position of the first block of the latent buffer, so the last block reads an empty noise slice and raises an error. Here the buffer is allocated one extra block; the number of generated blocks is unchanged.
- **Conditions:**
  - kr60_none: the released default setting (the first context frame is re-encoded);
  - kr60_first: keep_first_frame (the opening's first latent frame always stays in the context).
- **Opening:** the opening image is input through the released code's start_frame path (9 copies VAE-encoded as the first 3 latent frames). 8 copies of the opening image are prepended to the output video, so frames 0–8 are the opening (as for MAGI-1).
- **A Tone:** the 24 scenes of preregistration 06 (rx00–rx11, gx00–gx11), openings L\* −16 / +16, generic prompt, 60 s, seed 0. 24 × 2 × 2 = 96 videos in total.
- **B Content:** the 24 openings of preregistration 09, generic city prompt (arm mis), 60 s, seed 0; 8 fresh starts of the generic prompt per condition (seeds 0–7). 24 × 2 + 2 × 8 = 64 videos in total. The primary analysis uses CLIP ViT-L/14 embeddings (`clip_probe.py`); SigLIP so400m embeddings (`siglip_probe.py`) are also computed, for secondary analyses only.
- **Execution:**
  - A: one task per scene per condition (both versions in the same task); B: one task per opening (both conditions); fresh: one task per condition;
  - GPU: A40 only (same architecture, checked by arch_guard);
  - task lists generated by `make_krea_tasks.py` (`jobs/krea_a.jsonl`; embeddings `jobs/krea_e.jsonl`).
- **Trial:** before generation, only a 20-s trial of 1 scene (rx00) was run, to check memory, speed and whether the code runs (the results do not enter the analysis):
  - peak GPU memory 40.2 GiB on A40, about 12 s per block (about 16 min for a 60-s video);
  - in both conditions α fell to about 0.1 within about 6 s: at [10, 20) s it was −0.11 without the anchor and −0.02 with the first-frame anchor; in both conditions the scene became a generic city street within about 6 s.

## Metrics
- **Tone:** α(T) = (p16 end − m16 end)/(p16 opening − m16 opening); the opening is the mean L\* of frames 1–8, the end is the mean over [T − 10, T) s after the opening.
- **Content (as in preregistration 16 A):**
  - class score z = scale × (cos(frame, class label) − cos(frame, city label));
  - s[t0, t1) is the mean z within [t0, t1) s after the opening (frame f corresponds to (f − 9)/16 s), s_open is the mean over frames 1–8;
  - μ is the mean of the same window over the fresh starts of the same condition;
  - κ = (s − μ)/(s_open − μ), undefined when s_open − μ < 2.
- No collapse exclusion rule; the number of collapsed scenes is reported as a secondary result.

## Hypotheses (`analyze_krea.py`, frozen; Holm correction, 5 tests in total)
- **A1 the released window forgets the opening:** α(kr60_none, 60) − α(kr60_none, 10) < 0.
- **A2 the first-frame anchor keeps more:** α(kr60_first, 60) − α(kr60_none, 60) > 0.
- **A3 the anchor keeps a share:** α(kr60_first, 60) > 0.
- **B1 content relaxes under the released setting:** s[55, 60)(kr60_none) − s_open < 0.
- **B2 the anchor keeps more content:** κ[55, 60)(kr60_first) − κ[55, 60)(kr60_none) > 0.
- **Test method:**
  - two-sided one-sample t-tests over scenes (A) or openings (B);
  - supported if Holm p < 0.05 and the estimate is on the predicted side;
  - 95% CIs by bootstrap (10,000 draws; A resamples scenes, B resamples openings within class and resamples the fresh seeds).

## Secondary analyses
- α and 1-s curves of each condition at 10, 20 … 60 s;
- A1–A3 in the [40, 50) s window;
- κ curves of each condition (T = 5…60);
- B1, B2 on tone-removed embeddings;
- top-1 accuracy of the opening's class in [55, 60) s; κ per class;
- B1, B2 redone with SigLIP embeddings (encoder robustness);
- collapse check: number of scenes in which either version has a 1-s mean L\* below 3 or above 97.

## Predictions
- **A1 holds:** under the released setting α is close to 0 at 60 s.
- **A2, A3:** the paper's conclusions predict that they hold (an opening that stays in the context keeps a share). But in the single-scene trial the anchor kept no tone after 10 s, so this is uncertain here. If they do not hold, then on this model an anchor that takes up only one latent frame and is positioned right next to the window is not enough to keep the opening.
- **B1 holds.**
- **B2:** as A2, uncertain.
