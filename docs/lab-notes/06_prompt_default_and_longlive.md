# 补充实验：默认亮度由提示词决定？换一个模型还成立吗？（2026-10-19，探索性）

两个实验都没有预注册，属于探索性检验。目的是回答前面留下的两个问题：
1. "回归到默认亮度（≈33）"中的这个默认值，是模型固有的，还是由文字提示词决定的？
2. "回归到默认亮度"和校正方法，换到第二个模型（LongLive 1.0）上还成立吗？

## 实验 1：光照提示词

**设计。** 用和真实开头实验相同的 40 张开头帧：20 张 NAVSIM 真实前视图（real00–19），20 张模型自己生成的第一帧（self00–19）。每张开头帧固定 0.5 秒，之后分别在 4 种光照提示词下续写到 31 秒：sunny（晴天正午）、overcast（阴天）、dusk（黄昏）、night（夜晚）。提示词文件是 `prompts/lighting.jsonl`。每种组合 2 个种子，不做校正，共 320 个视频。原来通用提示词（generic）下的 real/self 视频作为第 5 个水平一起分析。分析脚本是 `analyze_light.py`，结果在 `results/corr/light_out/`。

**结果。**

| 提示词 | 零漂移亮度 L\*（开头帧聚类 bootstrap 95% CI） | 斜率 | R² | 31 秒时平均亮度 |
|---|---|---|---|---|
| sunny | 42.9 [41.0, 44.7] | −0.66 | 0.74 | 42.4 |
| generic（原实验） | 33.1 [30.4, 35.0] | −0.69 | 0.82 | 35.7 |
| overcast | 33.6 [30.7, 35.4] | −0.76 | 0.77 | 35.5 |
| dusk | 19.1 [14.3, 21.2] | −0.83 | 0.80 | 22.8 |
| night | 16.0 [12.5, 19.9] | −0.95 | 0.85 | 17.4 |

- 共同斜率的 ANCOVA 模型为 `dL_end ~ L_open + light`，R² = 0.90（只用开头亮度时为 0.82）。
  - 光照项 F 检验 p ≈ 4.5×10⁻⁷⁸。
  - 以 overcast 为基准：night −18.1 [−19.9, −16.4]，dusk −12.7，sunny +6.9 [+5.1, +8.6]，generic +0.2 [−1.5, +2.0]。
  - 共同斜率 −0.78 [−0.83, −0.72]。也就是说，开头帧的亮度偏差 31 秒后只剩约 22%。
- 斜率随提示词不同而不同（交互项 p = 0.011）。提示词越暗，回归越彻底（night −0.95，sunny −0.66）。
- 时间进程（相对开头帧的平均变化）：dusk 约 5.6 秒走完一半，night 约 11 秒。

**解读。**
- "默认亮度"不是模型固定的一个数，而是**每个提示词各有自己的默认亮度**。原先的 ≈33 只是通用驾驶提示词的默认值，恰好和 overcast 一样。
- 所以"漂移"更准确的说法是：模型逐渐忘掉开头画面，回到文字描述的场景。开头帧只能维持几秒的影响，之后由文字主导。
- **局限：**
  - 只有一个模型，每种组合 2 个种子。
  - dusk/night 这类提示词本身可能包含"天在变暗"的语义。所以这里测到的是"提示词设定的目标亮度"，不能把它们的变暗都算作模型缺陷。

## 实验 2：第二个模型 LongLive 1.0

**模型。** NVlabs LongLive-1.3B：Wan2.1-T2V-1.3B，加上 rank-256 LoRA（用 peft 加载），4 步去噪，滚动窗口 12 + sink 3。它的生成循环和 Self Forcing 相同，所以校正代码几乎可以直接移植（`ll_gen.py`）。设置用 LongLive 官方的默认值，不是 Self Forcing 的 w21s3。

**设计。** 每个提示词的所有分支在同一个任务里按顺序跑完，保证同一块 GPU、配对成立。共 120 个任务，600 个视频。
- A. 40 张开头帧（同上，通用提示词）× 种子 0,1 × {不校正, ttc_s1}。
- B. 原实验的 40 个 main 提示词（20 个 MovieGen + 20 个驾驶）× 种子 0,1 × {不校正, ttc_s1, ttc_s1_b15}。另有每个提示词 5 个 5 秒短视频，作为该提示词的参照分布。

### 2a. 回归到默认亮度（`analyze_ll.py`，结果在 `results/corr/ll_out/`）

| | Self Forcing | LongLive |
|---|---|---|
| 斜率（95% CI） | −0.69 [−0.81, −0.57] | −0.74 [−1.01, −0.58] |
| 零漂移亮度 | 33.1 [30.4, 35.0] | **39.9 [37.5, 42.1]** |
| R² | 0.82 | 0.65 |
| 平均 \|dL\| | 8.1 | 7.0 |
| 残差 SD / 同一开头帧种子间 SD | 3.1 / 4.1 | 5.2 / 3.6 |

- **规律在第二个模型上复现了：** 斜率几乎一样（模型 × 开头亮度交互 p = 0.59）。
- 不同的是默认亮度：LongLive 的默认亮度更高，约 40（两个 CI 不重叠）。
- 冒烟测试里"LongLive 几乎不变暗"，原因是真实开头帧（平均 47）离它的默认亮度更近，并不是回归更弱。
- R² 较低（0.65），残差更大，说明 LongLive 上开头亮度之外的因素更多。
- 一个新现象：在 LongLive 上，同样亮度的真实开头帧比模型自己生成的开头帧多变暗 4.3 L\*（p = 0.033，探索性）。在 Self Forcing 上这个差异不存在（p = 0.80）。所以"真实帧变暗更多只是因为它更亮"这个结论只在 Self Forcing 上成立。

### 2b. 校正（ttc_s1，β = 1；β = 1.5）

**真实/自生成开头帧（`analyze_real.py`，结果在 `results/corr/ll_open_out/`）。**
- ttc_s1 让 31 秒时的颜色偏移 dE 从 10.6 降到 8.5（−2.0 [−3.7, −0.6]）。
- |dL| 从 7.4 降到 5.2（−2.1 [−3.8, −0.6]），40 个场景中 30 个改善。
- 饱和度偏移也减小。
- 闪烁 jitter ×1.09，chunk 边界跳变 ×1.04。

**40 个 main 提示词（冻结的 `analyze_confirm.py`，结果在 `results/corr/ll_confirm_out/`）。** 与 Self Forcing 的确认性实验对比如下。注意两边的提示词集不同（Self Forcing 用 40 个 held-out 提示词 × 4 种子，LongLive 用 main 40 × 2 种子），所以只能粗略比较。

| | Self Forcing（确认性实验） | LongLive |
|---|---|---|
| 不校正时的 z_L（结尾亮度） | −2.19 | **−0.67** |
| 不校正时的 D | 5.78 | 5.58 |
| D 变化，β = 1 | −1.48 [−1.76, −1.19] | −0.70 [−1.13, −0.27] |
| D 变化，β = 1.5 | −1.78 [−2.11, −1.45] | −0.45 [−0.96, +0.06] |
| z_L 变化，β = 1 | +1.08 | +0.38 [+0.04, +0.73] |
| 结构 K | 非劣 | 非劣（β = 1：+0.05 [−0.10, +0.20]） |
| 闪烁 jitter，β = 1 / 1.5 | ×1.13 / ×1.67 | ×1.10 / ×1.41 |

- 校正在 LongLive 上**仍然有效，但效果大约只有 Self Forcing 上的一半**。
- 原因是 LongLive 在这些提示词上本来就几乎不变暗（z_L −0.67）。它的 D 主要来自亮度以外的分量，而校正只纠正整体色调（DC 分量）。
- β = 1.5 在 LongLive 上不比 β = 1 好，甚至略微矫枉过正（结尾 dL +0.9）。

## 修正后的整体说法
- 自回归视频扩散中的亮度漂移，可以统一描述为：**长时间生成中，开头帧的影响衰减，亮度回归到提示词所规定的默认水平**。斜率约 −0.7 到 −0.8，两个模型一致。
- 默认水平由提示词决定（16–43）。在同一个提示词下，不同模型的默认水平也不同（33 vs 40）。
- 内容感知校正在两个模型上都能减少漂移、不损害结构。效果大小取决于该模型本来漂移多少。
