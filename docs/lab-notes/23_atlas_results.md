# 结果：60 秒持续度图谱，sink 大小与位置编码（预注册 10，2026-10-25）

- **执行情况：** 792 个视频全部完成，全部在 A40 上（UI-GPU-HM 4×A40 通道，加 all.q 上只用 A40 的倒序补充任务；同一架构下输出逐位相同）。分析用冻结的 `analyze_atlas.py`（SHA-256 6891bdb8…，核对一致），结果在 `results/corr/atlas_out/`。偏离：执行方式从 all.q 数组改为非抢占通道 + 只用 A40 的数组，不影响配对和分析。

## 主要假设（Holm 校正，4 个检验）——全部成立
| 假设 | 两臂 | 差 [95% CI] | Holm p | 结论 |
|---|---|---|---|---|
| H1：更深的 sink 保留更多 | sink 6 0.76 vs sink 3 0.61 | **+0.15** [0.11, 0.20] | < 10⁻⁶ | 成立 |
| H2：任何 sink 都保留一些 | sink 1 0.29 vs 无 sink 0.05 | **+0.24** [0.14, 0.34] | < 0.001 | 成立 |
| H3：LongLive 的 sink 在 60 秒仍然保留 | 0.45 vs −0.01 | **+0.46** [0.39, 0.53] | < 10⁻¹⁰ | 成立 |
| H4：sink 的位置编码有影响（双侧） | 重新旋转 0.16 vs 原始 0.61 | **−0.44** [−0.54, −0.35] | < 10⁻⁷ | 成立（重新旋转后保留得少得多） |

- 31 秒时"sink 1 比无 sink 保留得少"的探索性异常，在 60 秒消失并反转：持续度随 sink 深度单调增加（0、1、3、6 帧：0.05、0.29、0.61、0.76），与递推模型一致。
- 把 sink 的键重新旋转到窗口前面（Rolling Forcing、Deep Forcing 的做法），Self Forcing 的保留从 0.61 降到 0.16；sink 1 也从 0.29 降到 0.08（−0.21 [−0.31, −0.11]）。

## 次要分析：32 秒附近的跳升来自位置编码
| 配置 | α(34.5 秒) − α(31.5 秒) |
|---|---|
| sink 3 | **+0.45** [0.36, 0.53] |
| sink 6 | **+0.46** [0.38, 0.54] |
| sink 3 重新旋转 | −0.08 [−0.13, −0.02] |
| 无 sink | −0.08 [−0.14, −0.03] |
| sink 1 | +0.05 [−0.07, 0.18] |

- 重新旋转之后跳升消失。所以跳升（以及内容研究中开头内容在后期"回来"）是 sink 保留绝对位置造成的：当前段与 sink 的距离到某些值时，模型强烈关注 sink，把开头重新带回来，与 LoL 的 "sink collapse"（RoPE 周期性）一致。
- 这也说明 Self Forcing 的 sink 在 60 秒保留的大部分来自这种位置效应；在训练分布内的相对位置下（重新旋转），sink 只保留 0.16。

## 次要分析：开头是"一开始被拒绝"还是"慢慢被忘掉"
- 4.5 秒内丢失的比例 / 60 秒总丢失：SiD 0.66 / 0.65（几乎全部在开始几秒丢失，像是模型拒绝了这种人为平移）；Self Forcing 无 sink 0.24 / 0.95、sink 1 重新旋转 0.20 / 0.92（主要是慢慢遗忘）；sink 6 0.18 / 0.24。
- 零漂移亮度（60 秒）：SiD v2 12.9、GAN 20.6、Self Forcing 10 秒 35.5、LongLive 37.9（无 sink 40.3）、Rolling Forcing 56.2、SiD 59.6。
